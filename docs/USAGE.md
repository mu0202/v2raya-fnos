# 使用说明

## 安装

1. 下载 `v2raya_<version>_x86.fpk`
2. 飞牛 **应用中心 → 手动安装**，选择该文件
3. 安装完成后桌面出现 v2rayA 图标

**平台要求**：x86_64，fnOS ≥ 1.1.3100。

应用以 root 运行（TUN 与透明代理需要），安装时会提示。

## 首次使用

打开桌面图标后，在页面中**创建管理员账户**。账户信息保存在应用数据库中，
不经过飞牛账户体系。

登录后可添加节点：

- **订阅** —— 粘贴订阅链接，自动拉取节点列表
- **手动** —— 逐个填写服务器信息

节点与订阅的管理完全使用 v2rayA 自身的界面，与官方版本一致。

## 代理模式

在 **设置 → 透明代理/系统代理** 选择运行方式：

| 模式 | 作用范围 | 说明 |
| --- | --- | --- |
| `tun` | 整机全部流量 | 创建 TUN 设备接管流量，兼容性最好 |
| `tproxy` | 本机 TCP/UDP | 依赖 iptables TPROXY，UDP 支持完整 |
| `redirect` | 本机 TCP | 最轻量，仅 TCP，UDP 不经过代理 |
| 不启用 | 手动指定 | 只开 SOCKS/HTTP 入站，由程序自行配置 |

保存后点「启动」生效。三种方式的网络规则都由 v2rayA 自己创建与清理，
本包不参与。

## 局域网访问

默认只有 NAS 本机能用代理。要让局域网内其他设备走代理：

1. **设置 → 允许局域网的连接**（`portSharing`）打开
2. 客户端指向 `NAS地址:20170`（SOCKS5）或 `NAS地址:20171`（HTTP）

这两项会把入站监听从 `127.0.0.1` 放宽到 `0.0.0.0`。

> 把 NAS 当作整个局域网的**透明网关**（客户端无需改配置即可走代理）
> 属于系统层面的网络改造，不在本包范围内。

## DNS 与 DoH

v2rayA 没有独立的「DoH 开关」，DoH 是通过 DNS 上游地址实现的：

1. 进入 **订阅 → 配置 → 节点 DNS**
2. 填入完整 URL，例如 `https://1.1.1.1/dns-query`
3. 确认 `dnsMode` 为 `hijack`（本包默认开启）

在 `tun` 模式下，进入 TUN 的 53 端口明文查询会被内核自身的 DNS 模块接管，
所以即使客户端配置了别的 DNS 服务器，最终仍由 v2rayA 解析。

## 日志

- **应用日志** —— 页面内 **日志** 页可实时查看
- **文件日志** —— `@appdata/v2raya/logs/v2raya.log`，默认保留 3 天

日志级别在 **设置** 页调整（`trace` / `debug` / `info` / `warn` / `error`）。

## 设置

本包的设置页只管飞牛侧的运行参数，共两项：

| 设置 | 取值 | 说明 |
| --- | --- | --- |
| 日志级别 | `trace` / `debug` / `info` / `warn` / `error` | 写入文件日志的详细程度 |
| IPv6 支持 | `auto` / `on` / `off` | 是否允许使用 IPv6 节点 |

保存后应用自动重启生效。代理相关的全部设置都在 v2rayA 页面内，
不在飞牛的设置页。

## 升级

在应用中心直接覆盖安装。数据库、节点、订阅、日志全部保留。

> 从早期 `2.5.16-1` ~ `2.5.16-3`（lite 模式，非 root）升级时，
> 旧的透明代理方式可能记录为 `system_proxy`，该值在 root 模式下无效。
> 升级后到 **设置 → 透明代理/系统代理** 重新选择一次并保存。

## 卸载

卸载向导会询问数据处理方式：

- **保留数据** —— 数据库与日志留在 `@appdata/v2raya`，重新安装后账户和节点都在
- **删除数据** —— 清空应用数据目录（数据库、日志、配置），不可恢复

默认保留。

## 常见问题

**核心启动失败**

打开 **日志** 页查看 `v2raya_core` 的报错。常见原因是规则库文件缺失或损坏——
执行 `bash scripts/fetch-payload.sh --force` 重新拉取后重装。

**GFWList 模式不可用**

该模式依赖 `LoyalsoldierSite.dat`。确认 `@appcenter/v2raya/target/assets/`
下三个 `.dat` 文件都存在且体积正常（`geoip` 约 5 MB 以上，`geosite` 约 10 MB 以上）。

**透明代理没生效**

1. 确认 **设置** 页的透明代理方式选了 `tun` / `tproxy` / `redirect`，
   而不是留空或 `system_proxy`
2. 确认主界面状态是「正在运行」而不是仅「已启动界面」
3. `redirect` 只处理 TCP，UDP 流量（DNS、QUIC）不会经过代理，属预期行为

**局域网设备连不上**

1. 确认 **允许局域网的连接** 已打开
2. 确认客户端填的是 NAS 的局域网 IP，不是 `127.0.0.1`
3. 若启用了防火墙，放行 `20170`（SOCKS5）与 `20171`（HTTP）
